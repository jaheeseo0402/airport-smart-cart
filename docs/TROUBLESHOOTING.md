# 겪었던 어려움과 해결 과정

프로젝트를 만들면서 실제로 막혔던 문제를 **증상 → 원인 → 해결 → 배운 점** 순서로 정리했습니다.
원인을 끝까지 확인하지 못한 항목은 "미확인"으로, 아직 해결하지 못한 항목은 맨 아래 "남은 문제"에 적었습니다.

---

## 1. ESP32가 USB 장치로 인식되지 않음 → 아두이노 우노로 변경
- **증상**: 라즈베리파이(`lsusb`)와 노트북(COM 포트 없음) 양쪽에서 ESP32가 USB 장치로 보이지 않았습니다.
- **원인**: 케이블이나 센서 배선 단락을 의심했으나 **끝내 확인하지 못했습니다(미확인)**. ESP32는 3.3V 보드라 초음파 ECHO 핀에 분압 저항도 필요해서 배선이 더 복잡했습니다.
- **해결**: 5V 신호를 쓰는 아두이노 우노로 바꾸고 전체 배선을 새로 했습니다. (ECHO 분압 저항이 필요 없어졌습니다)
- **배운 점**: 문제가 길어지면 보드를 바꾸는 것도 방법입니다. 다만 배선을 한꺼번에 바꾸면 원인을 찾기 어려워서, 이후에는 부품을 하나씩 따로 시험했습니다.

## 2. 초음파 값이 전부 `-1.0`으로 나옴
- **증상**: 4개 센서 값이 모두 `-1.0`(측정 실패)이었습니다.
- **원인**: 배선 접촉과 연결 문제였습니다. **단일 원인은 기록하지 못했습니다(미확인)**.
- **해결**: 센서를 **하나만 직접 연결**해서 값이 나오는지 보고, 되는 센서를 하나씩 늘려 가며 배선을 다시 했습니다. 그 뒤 앞·왼쪽·오른쪽·뒤를 순서대로 추가했습니다.
- **배운 점**: 여러 센서를 한꺼번에 연결하기 전에 **1개 → 2개 → 4개 순서로 확인**하면 문제 위치가 바로 보입니다. TRIG와 ECHO가 바뀌거나 전원선이 헐거운 경우가 많았습니다.

## 3. 초음파 값이 튀고 `126` 같은 값이 섞여 나옴
- **증상**: 아무것도 없는데 16cm와 60cm 사이를 오가거나 100cm 이상 값이 갑자기 나왔습니다.
- **원인**: 초음파는 부채꼴로 퍼져서 **바닥이나 가까운 면에 반사**된 값이 섞입니다. 센서가 낮거나 아래로 기울어 있으면 더 심합니다.
- **해결**: 센서를 수평으로 단단히 고정하고, 칼만필터로 값을 다듬고, **위험이 연속 3프레임 확인될 때만** 정지하게 했습니다. 측정 실패(`-1`)는 "멀다"로 처리했습니다.
- **배운 점**: 초음파 한 번의 값을 그대로 믿으면 안 됩니다. 필터와 연속 확인이 필요합니다.

## 4. 라인센서가 흰색과 검정 모두 `1`로 나오고 센서마다 값이 다름
- **증상**: 흰 바닥에서도 1이 나오고, 왼쪽과 오른쪽 센서의 값이 서로 달랐습니다. 센서를 따로 시험할 때는 잘 되다가 합치니 문제가 생겼습니다.
- **원인**: 센서마다 **검정에서 내는 값(0 또는 1)이 달랐고**, 감도(파란 가변저항)와 센서 높이 영향도 있었습니다.
- **해결**: 코드에 `BLACK_L`, `BLACK_R`를 따로 두고 센서별로 검정 값을 지정했습니다. 높이를 1~2cm로 맞추고 감도를 조절했습니다. (최종 `BLACK_L = 1`, `BLACK_R = 1`)
- **배운 점**: 같은 모델이어도 센서 값은 다를 수 있어서, 시리얼로 흰색과 검정 값을 직접 찍어 확인해야 합니다.

## 5. 바퀴가 뒤로 돌고 좌우가 바뀜
- **증상**: 전진 명령에 바퀴가 뒤로 돌았고, 왼쪽·오른쪽 모터도 서로 바뀌어 있었습니다.
- **원인**: 모터 두 선의 극성과 드라이버 채널(A/B) 연결이 코드의 가정과 달랐습니다.
- **해결**: 배선을 다시 뽑지 않고 **코드의 핀 번호만 교체**했습니다. (`LEFT_PIN1=10, LEFT_PIN2=9, RIGHT_PIN1=6, RIGHT_PIN2=5`)
- **배운 점**: 모터 방향은 배선 확인 코드(`wiring_check.ino`)로 `L`/`R`/`B` 명령을 보내 하나씩 확인하는 것이 빠릅니다.

## 6. 업로드할 때 `undefined reference to setup/loop` 컴파일 오류
- **증상**: 아두이노 IDE에서 `setup`과 `loop`를 찾을 수 없다는 오류가 났습니다.
- **원인**: 빈 스케치이거나 코드를 잘못 붙여 넣었고, 다른 탭의 코드가 섞여 있었습니다.
- **해결**: `Ctrl + A`로 전체를 지우고 코드 하나만 붙여 넣었으며, 새 스케치로 다시 만들었습니다.

## 7. 초음파 4개를 재는 동안 라인 따라가기가 길게 끊김
- **증상**: 센서를 한꺼번에 재면 그동안 모터 제어가 멈춰서 주행이 끊겼습니다.
- **원인**: 초음파 한 개를 재는 데 최대 12ms가 걸려서, 4개를 연속으로 재면 제어 주기가 길어졌습니다.
- **해결**: 센서를 **한 번에 하나씩, 25ms 간격으로 돌려가며** 재서 100ms에 한 번 4개 값을 전송합니다. 센서끼리 신호가 섞이는 것도 막았습니다.

## 8. 정지한 뒤 다시 출발하지 않음
- **증상**: 한 번 정지하면 `정지중`에서 `주행중`으로 돌아오지 않았습니다.
- **원인 1**: 측정 실패(`-1`)가 많으면 "모든 방향이 멀다"는 조건이 채워지지 않았습니다. → `-1`을 "멀다"로 처리하도록 수정했습니다.
- **원인 2**: 재출발 조건이 **네 방향 모두 50cm 이상**이라, 옆 벽이나 뒤 물체 때문에 영원히 출발하지 않았습니다. → **앞 센서가 30cm보다 멀면 재출발**하도록 바꿨습니다. (앞 20cm 정지, 30cm 재출발이라 경계에서 멈췄다 갔다 하지 않습니다)
- **배운 점**: 정지 조건과 재출발 조건을 같은 기준으로 두면 안 되고, 재출발 기준은 더 여유를 둬야 합니다.

## 9. 시리얼 포트와 전원 연결 때문에 생기는 문제
- 아두이노는 **파이 USB로 전원과 통신**을 같이 받습니다. 노트북과 파이에 동시에 꽂지 않습니다.
- 시리얼 포트를 열면 우노가 **리셋되어 5초 카운트다운이 다시 시작**되므로, 연결 후 5~6초 기다려야 합니다.
- 포트는 **한 프로그램만** 열 수 있어서 센서 시험 코드와 판단 코드를 동시에 실행할 수 없습니다. 아두이노 IDE의 시리얼 모니터도 닫아야 합니다.
- 모터 전원은 별도 배터리를 쓰고, **배터리 −와 아두이노 GND는 반드시 연결**합니다. 센서 VCC(아두이노 5V)와 모터 드라이버 VCC(모터 배터리 +)를 섞지 않습니다.

## 10. 왼쪽 바퀴가 더 느림
- **증상**: 같은 속도 값을 줘도 카트가 한쪽으로 휘었습니다.
- **해결**: 속도를 `leftSpeed = 170`, `rightSpeed = 150`으로 **따로 지정**하고, 시리얼 모니터에서 `+`/`-`로 왼쪽 속도를 5씩 바꿔 가며 직진이 곧게 되는 값을 찾을 수 있게 했습니다. (이 숫자는 시작값이며 실제 주행으로 맞춥니다)

## 11. 급커브에서 라인을 놓칠 수 있음
- **증상(예상)**: 라인이 직각에 가깝게 꺾이면 두 센서가 모두 흰색이 되어 정지합니다.
- **해결**: 마지막으로 라인을 본 쪽으로 제자리 회전하며 라인을 다시 찾는 로직을 추가했습니다. 3초 안에 못 찾거나 직선 끝에서 놓친 경우에는 정지합니다. 파이의 "라인 이탈" 판정 시간은 4초로 늘렸습니다.
- **상태**: 센서 값을 흉내 낸 **모의 시험으로만 확인**했고 실물 주행 결과는 아직 기록하지 못했습니다.

## 12. 처음 만든 웹 코드에 비밀키와 비밀번호가 들어 있음
- **문제**: 데모 코드에 세션 비밀키, QR 서명 비밀키, 로그인 비밀번호가 그대로 있어서 공개 저장소에 올리면 노출됩니다.
- **해결**: 비밀값을 코드에서 지우고 환경변수로만 받게 했습니다. 이후 웹을 팀원이 만든 버전으로 교체하면서 같은 처리를 다시 했습니다(16번).

## 13. 배선확인코드는 되는데 최종 코드에서는 앞 초음파만 읽히던 문제
- **증상**: 앞만 값이 나오고 왼쪽/오른쪽/뒤는 손을 가까이 해도 `-1`.
- **시도**: 센서 시험용 코드(범위를 넓게 150/100/100/100cm, 모터 꺼짐)로 확인하니 4개 모두 정상으로 읽혔습니다.
- **원인(추정)**: 옆/뒤의 최대 측정거리를 35/35/45cm로 너무 좁혀서 `pulseIn` 제한시간(약 2ms)이 짧았고, 에코 시작까지의 대기시간과 합쳐 측정 실패(-1)가 된 것으로 보입니다. 모터 노이즈 영향은 모터를 켠 상태에서 따로 확인 필요.
- **해결**: 범위를 앞 80cm, 옆/뒤 60cm로 되돌렸습니다. 교훈: 범위를 줄일 때는 줄인 값에서 에코 대기시간만큼 여유를 둬야 합니다.


## 14. 코드 파일을 메일에서 복사해 붙였더니 SyntaxError
- **증상**: `cart_web.py`를 실행하자 `SyntaxError: invalid character '•' (U+2022)`. 파일 23번째 줄에 `• Gmail에서 검사함`이 들어 있었습니다.
- **원인**: 파일을 첨부파일로 받지 않고 Gmail 미리보기 화면에서 내용을 복사해 붙여 넣어서, Gmail 화면의 안내 문구("스크린 리더로 Gmail 사용하기" 등)가 파일 안에 섞였습니다. 파일 3개 모두 같은 증상이었습니다.
- **해결**: 파일 내용을 복사하지 않고 첨부파일을 **다운로드해서 VS Code 파일 목록으로 끌어다 놓아** 교체했습니다. `grep -n "Gmail" *.py`로 섞인 글자가 없는지, `python3 -m py_compile 파일명`으로 문법을 확인했습니다.

## 15. 폰으로 QR을 찍었는데 사이트에 접속되지 않음
- **증상**: 웹은 켜 둔 것 같은데 폰에서 "사이트에 접근할 수 없음". 파이 안에서 `curl http://127.0.0.1:5000/` 결과가 `000`이었습니다.
- **원인(두 가지)**: 웹 프로그램이 꺼져 있었고, QR에 들어 있던 IP(`172.20.10.3`)가 파이의 실제 IP(`10.202.36.115`)와 달랐습니다.
- **해결**: 웹을 다시 켜고, `hostname -I`로 확인한 실제 IP로 `make_cart_qr.py`를 다시 실행해 QR을 새로 만들었습니다. 와이파이나 핫스팟이 바뀌면 IP도 바뀌므로 시연 전에 다시 확인합니다.
- **교훈**: 명령어의 `파이IP` 같은 자리표시를 그대로(한글로) 입력하지 않고 실제 숫자로 바꿔 넣어야 합니다.

## 16. QR 서명 키가 코드에 그대로 있었음
- **문제**: QR 서명 키의 기본값이 코드에 들어 있어서 공개 저장소에 올리면 누구나 위조 QR을 만들 수 있었습니다.
- **해결**: 기본값을 지우고 `CART_SECRET`, `FLASK_SECRET` 환경변수로만 받게 했습니다. 키를 바꾸면 서명이 달라져 이전 QR은 거부되므로 QR을 새로 만들어야 합니다.


## 17. 카메라(YOLO)를 켜지 못했다는 경고
- **증상**: `cart_bridge.py` 실행 시 `[경고] 카메라(YOLO)를 켜지 못했습니다 ... No module named 'ultralytics'`.
- **원인**: YOLO 패키지(`ultralytics`)가 파이에 설치되어 있지 않았습니다.
- **해결**: `pip install ultralytics --break-system-packages`로 설치한 뒤 `python3 yolo_detector.py`로 카메라를 단독 확인했습니다. 카메라는 한 프로그램만 쓸 수 있어서(다른 프로그램이 쓰면 `Device or resource busy`) 단독 실행은 끄고 `cart_bridge.py`를 켭니다.
- **참고**: 카메라를 못 켜도 경고만 내고 초음파/라인만으로 동작하도록 만들어서, 카메라 문제가 주행을 막지 않습니다.

## 18. 사람 인식은 되는데 정지 기준을 어떻게 정할지
- 사람 수만 맞게 나온다고 멈추는 것은 아니고, 사람 박스가 화면에서 차지하는 비율(`max_area`)이 기준(`PERSON_AREA_STOP`, 기본 30%) 이상이어야 정지합니다.
- 폰 화면의 전신 사진을 정지시키고 싶은 거리에 두었을 때 박스 크기가 39~50%로 측정되어 30%를 유지했습니다. 멀리 둘 때의 값도 확인해 오탐(멀리서 멈춤)이 없는지 보고 조정합니다.

## 남은 문제 (해결 못 함)
- **앞 초음파가 아무것도 없는데 튀는 현상**: 바닥 반사 가능성이 커서 센서 높이와 각도를 조정해 확인하는 중입니다.
- **라인 추종이 잘되다 안되다 하는 현상**: 센서 높이, 가변저항 감도, 바닥 반사, 배터리 전압, 속도를 점검하는 중입니다.
- **카메라(YOLO)의 주행 중 정지 시험**: 사진 기준 감지는 확인했고, 주행 중 정지 거리와 오탐은 라인 환경에서 확인할 예정입니다.
