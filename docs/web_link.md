# 웹과 카트 연동

웹(`web/cart_web.py`)과 카트 프로그램(`raspberry_pi/cart_bridge.py`)은 **서로 다른 프로세스**이고, 파이 안에서 HTTP(127.0.0.1:5000)로만 이야기합니다.
시리얼 포트는 `cart_bridge.py`만 열기 때문에 포트 충돌이 없습니다.

## 승객 흐름 (phase)

| 단계 | 상태(`phase`) | 일어나는 일 |
|---|---|---|
| 1 | idle -> ready | 승객이 카트 뒤 QR을 찍음. 서명이 맞으면 그 폰이 카트를 점유 |
| 2 | driving | 탑승구(A/B) 선택 -> 카트가 라인을 따라 출발. 장애물이 있으면 정지, 치우면 재출발 |
| 3 | arrived | 카트가 게이트 앞에서 정지 (`TRIP_SECONDS` 시간 기준) |
| 4 | returning | 승객이 반납 -> 잠금 해제, 카트가 우회 통로(게이트 뒤로 이어진 라인)를 따라 출발점으로 이동 (`RETURN_LAP_SECONDS`) |
| 5 | idle | 출발점에서 정지하고 복귀 완료를 보고. 다음 승객이 QR을 찍을 수 있음 |

## 카트 <-> 웹 주소 (파이 안에서만 접근 가능, 밖에서는 403)

```
GET  /robot/command -> {"phase": "driving", "gate": "A", "stopped": false}
POST /robot/status  -> {"progress": 0.4, "message": "...", "tier": "위험", "ttc": 1.6}
                       도착: {"arrived": true} / 복귀 완료: {"returned": true}
```

- 카트는 `command`를 0.1초마다 읽고, `phase`가 `driving` 또는 `returning`이면서 `stopped`가 `false`일 때만 달립니다. 웹에 연결이 안 되면 정지합니다.
- 안전 정지(초음파, 라인 이탈)는 웹 명령과 상관없이 항상 우선합니다.
- 위험 단계(`tier`): 안전 / 주의 / 위험 / 임박 / 정지

## 보안

- QR에는 `http://<파이 IP>:5000/c/<카트번호>?sig=<HMAC-SHA256 서명 앞 16자리>`가 들어갑니다. 카트 번호나 서명이 다르면 거부(403)합니다.
- 서명은 변조를 막지만 QR 사진을 찍어 복사하는 것은 막지 못해서, **먼저 찍은 폰만 조종**하는 점유 잠금을 함께 씁니다. 다른 폰은 "사용 중"(409), 점유하지 않은 폰의 조작은 거부(403)합니다.
- 서명 키(`CART_SECRET`)와 세션 키(`FLASK_SECRET`)는 환경변수로만 받습니다. 없으면 실행되지 않습니다.
- 한계: 로그인이 없으므로 QR을 먼저 찍은 사람이 카트를 차지합니다. 실제 서비스에서는 손잡이 물리 버튼이나 근접 확인이 필요합니다.
- 도착과 복귀는 센서가 아닌 시간 기반 단순화입니다.
